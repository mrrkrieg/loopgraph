       → task loops

3. Runtime engine
The graph should not just be visual. It should execute:
event arrives
→ management loop evaluates company state
→ calls relevant department loop
→ department loop calls workflow loop
→ workflow loop uses integrations/tools
→ verifier checks output
→ human review if needed
→ trace is saved
→ metrics update
→ improvement loop learns from failures

3. The loop execution model
Every loop should run through the same canonical state machine.
DRAFT
 → CONFIGURED
 → READY
 → ACTIVE
 → RUNNING
 → WAITING_FOR_REVIEW
 → VERIFIED
 → COMPLETED
 → LEARNING
 → ACTIVE
Failure states:
FAILED_VERIFICATION
ESCALATED
PAUSED_BY_POLICY
BUDGET_EXCEEDED
INTEGRATION_ERROR
NEEDS_CONFIGURATION
Runtime sequence
1. Trigger
2. Hydrate context
3. Load company / department / loop instructions
4. Load integration variables
5. Run planning step
6. Execute routine
7. Call tools
8. Verify output
9. Escalate if needed
10. Commit approved action
11. Save trace
12. Update metrics
13. Write memory
14. Feed improvement loop
15. Report summary to parent loop
In pseudocode:
async function runLoop(loopId: string, event: LoopEvent) {
 const loop = await loopStore.get(loopId)


 const context = await contextCompiler.compile({
   companyId: loop.companyId,
   departmentId: loop.departmentId,
   loopId,
   event,
 })


 const run = await traceStore.startRun({ loopId, event, context })


 const plan = await agent.plan({ loop, context, event })


 for (const step of plan.steps) {
   const result = await toolRunner.execute(step)
   await traceStore.recordToolCall(run.id, step, result)


   if (result.requiresEscalation) {
     return await humanReview.create({ runId: run.id, reason: result.reason })
   }
 }


 const verification = await verifier.verify({ loop, run })


 if (!verification.passed) {
   await traceStore.recordVerification(run.id, verification)
   return await escalationPolicy.handle({ loop, run, verification })
 }


 await outputCommitter.commit({ loop, run })
 await memory.writeFromRun(run.id)
 await metrics.updateFromRun(run.id)
 await improvement.enqueue(run.id)


 return await traceStore.finishRun(run.id)
}

Example agent.md:
# Campaign Learning Loop Agent


## Loop Goal


Reduce cost per qualified customer by improving campaign learning velocity.


## Department


Marketing.


## Company Goal


Increase qualified pipeline without reducing brand trust or customer fit.


## Inputs


- Ad platform performance
- Web analytics
- CRM qualified lead status
- Campaign spend
- Landing page conversion data


## Allowed Actions


- Summarize campaign performance
- Generate campaign hypotheses
- Recommend budget changes
- Draft experiment brief
- Request human approval for spend or brand-sensitive copy


## Forbidden Actions


- Launch external campaigns without approval
- Increase budget without human review
- Make unsupported claims
- Change attribution definitions


## Verification


Output must include:
- source data references
- cost per qualified customer
- hypothesis
- expected measurement window
- risk level
- required human approval if spend changes


## Escalation


Escalate when:
- budget change exceeds threshold
- claim is legally or brand sensitive
- data is inconsistent
- confidence is low

10.2 Net saved formula
gross_saved =
 baseline_minutes_per_item * items_processed


hidden_cost =
 review_minutes
 + rework_minutes
 + botsitting_minutes
 + escalation_minutes
 + governance_minutes


net_saved =
 gross_saved - hidden_cost
10.3 Quality-adjusted productivity
quality_adjusted_output =
 sum(outputs * quality_score * business_weight) / total_human_minutes
10.4 Relationship redeployment
relationship_redeployment =
 min(net_saved, observed_relationship_hour_increase)
This matters because saved time should not be assumed to become higher-value human work; it must be observed through calendars, CRM logs, project systems, time diaries, and management review.

17. Open-source release structure
The README should make the value obvious in the first 20 seconds.
README positioning
# Loopgraph


Open-source infrastructure for designing, running, tracing, and improving company loops.


Loopgraph lets teams model a company as a graph of management, department, workflow, verification, human-review, memory, and improvement loops. Developers can connect their own systems of record, define loop context, run agents safely, and measure net value after review, rework, escalation, governance, and botsitting costs.
What to emphasize
Not another chatbot.
Not another workflow automation builder.
Not just an agent framework.
Not just a graph editor.


A loop operating layer for AI-human company workflows.

19. Exact Codex task
Give Codex this as the next implementation task.
Implement Loopgraph Open Source Core v0.1.


Goal:
Build the open-source core for Loopgraph: a system for defining, visualizing, executing, tracing, and measuring company management loops. Loopgraph models a company as a graph of company, department, management, workflow, task, integration, verifier, human-review, memory, metric, guardrail, and improvement nodes.


The core concept:
A loop is not a prompt. A loop is a recurring AI-human feedback system with goal, signals, context, integrations, routines, verification, escalation, memory, metrics, budget, risk, and trace learning.
